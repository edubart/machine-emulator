## How the Dave node drives the emulator (exact map)

Dave pins **emulator v0.21.0** (`machine/script/cartesi-machine-source.sh:12-13`, commit `bd09538`), built static `release=yes slirp=no` via the Rust `cartesi-machine-sys` crate (`machine/rust-bindings/cartesi-machine-sys/build.rs`). The safe wrapper `cartesi-machine/src/machine.rs` makes 1:1 C API calls. The on-chain step is `machine-solidity-step` @ `23765c8` (v0.15.0 / emulator v0.21, `CM_MARCHID` 21). **No JSON-RPC / remote / fork / clone_empty anywhere** (the `remote_machine` cargo feature is off; node and Lua client both use only the in-process local machine). v0.22 adds `cm_collect_mcycle_bundle`/`cm_collect_uarch_cycle_bundle` and widens the CMIO `length` arg to `uint32_t` — Dave uses neither new entry point.

Two drivers exist and use the **same** emulator-call subset:
- **Rust node** (`cartesi-rollups/node/src`), production. Threaded, one `Machine` (`!Send+!Sync`) per thread.
- **Lua PRT client** (`prt/client-lua/computation/machine.lua`), the reference player, `cartesi.machine{...}` in-process.

### Configs / runtime configs / sharing modes
- **Runtime config**: always `RuntimeConfig::quiet_console()` (`config/runtime.rs:140`): console `to_null`/`from_null`, `skip_version_check=false`, `soft_yield=false`, `no_reserve=false`. Leaf (per-ustep) builds set `concurrency.update_hash_tree=1` (serial hashing, `machine_stf.rs:104-110, runtime_config()`); sampled builds leave it 0 (parallel).
- **Template**: the operator's program image (`cartesi-machine --store`, `test/programs/script/build-echo.sh`). `Template::inspect` (`storage/open.rs:106-121`) loads it `SHARING_NONE`, takes the root, `reset_uarch`, and **refuses it if the root changes** (pristine-uarch gate — this is the out-of-band check BUGS.md CM-02 asks for). Must await an RX_ACCEPTED yield.
- **Create from config** only in tests/measure (`default_config` + edits); production never `cm_create`s a rollup machine.
- **Sharing**: committed snapshots load `CM_SHARING_NONE` (`Machine::load`, `rollups_machine.rs:256`); the live working clone loads `CM_SHARING_ALL` (`load_shared`, `:267-279`); `cm_store` is always `CM_SHARING_ALL` (`machine.rs:257-263`). `CM_SHARING_CONFIG` is never used. (So the whole class of BUGS.md `sharing:config` / per-drive-hash-tree-file bugs is out of Dave's reach.)

### The boundary store (`storage/snapshots.rs`), content-addressed by root hash
- `checkout` = `cm_clone_stored(from, .work-PID-SEQ)` (`:249-258`).
- `stage_machine_store` = `cm_store(SHARING_ALL)` into `.part-PID-SEQ`, then `publish_staged` (`:155-245`).
- `publish_staged` = load the staged dir `SHARING_NONE`, read its root, **assert it equals the CAS key**, `cm_sync_stored`, `cm_rename_stored` (no-replace) to `snapshots/0x<hash>` (`:203-245`).
- `commit_boundary_machine` (`:136-152`) asserts `cm_get_root_hash == key`, stages, registers.
- `sync_stored`/`rename_stored`/`remove_stored` used for durability, adoption, GC.

### The runner (`machine_runner/mod.rs` + `storage/advance.rs`)
Per gap-sized batch: `begin_advances_at` (`advance.rs:358`) `checkout`s the newest boundary, `load_shared` (SHARING_ALL), and **asserts the loaded root == the row** (`assert_runner_boundary_root`). Per input: one window-sized `Ruler::collect` at the pinned root stride (two-level geometry `[38,0]/[54,38]`, so stride 2^38 meta-cycles = 2^18 big cycles; coarse mode = `cm_run` in chunks, `ruler.rs:400-470`). `record_accepted` (`:407`) `cm_get_root_hash` (brings sidecars exact) → `close` (drop) → `checkout` → `load_shared` (rotate_accepted); `record_reverted` (`:484`) discards the poisoned clone and re-clones the checkpoint. `commit_advances` publishes only the final boundary. `roll_epoch` (`:633`) loads the latest, computes the settlement root, captures the **machine validity proof** = three word proofs (`cm_get_proof(addr & ~31, log2=5, log2_root=64)` + `cm_read_memory`) at `iflags_Y`, `HTIF tohost`, `TX_START`, folded to the root (`rollups_machine.rs:184-210`), then `store_boundary`.

### The feed/step engine (`engine/machine_stf.rs` + `engine/ruler.rs`)
- `feed` (window open, `:324-406`): `cm_get_root_hash` = revert root; Store mode = `commit_boundary_machine`; **Bulk collector only**: `cm_collect_uarch_cycle_root_hashes(mcycle, 0, NULL)` on the yielded machine for the revert tail; then `cm_send_cmio_response(ADVANCE, payload, revert_root)`.
- `ustep` = `cm_run_uarch(ucycle+1)`; `ureset` = `cm_reset_uarch` then `restore_rejected`; `restore_rejected` (`:275-298`) on an RX_REJECTED yield reloads the pre-feed checkpoint `SHARING_NONE` and **asserts it hashes to the revert root**.
- `run_big` = `cm_run(target)` loop (`:424-447`).
- Tall-leaf **Bulk** `big_cycle_roots` (`:448-505`): `cm_collect_uarch_cycle_root_hashes(chunk_end, LOG2_MAX_UARCH_CYCLES_PER_MCYCLE=20, revert_tail)` in 256-mcycle chunks, capped at `imcyclemax-1` (seam-1 handling).
- **Proving** (`ruler.rs:488-529`, identical in the Lua client `machine.lua:481-525`): window open = `cm_log_send_cmio_response(ADVANCE, payload, revert_root, LogType::default())` + `cm_log_step_uarch`; closing slot = `cm_log_step_uarch` + `cm_log_reset_uarch`; interior = `cm_log_step_uarch`. Verified with `cm_verify_send_cmio_response` / `cm_verify_step_uarch` / `cm_verify_reset_uarch` (NULL machine, static). **`cm_log_step(N)` / `cm_verify_step(N)` are never called.**

### Loads / forks / rollbacks / replaces
- Load: `cm_load_new` (NONE for committed, ALL for the live clone). **Never `cm_replace_memory_range`, `cm_read/write_virtual_memory`, `cm_translate_virtual_address`, `cm_collect_mcycle_root_hashes`, or any multi-mcycle `cm_log_step`.**
- Fork: filesystem clone chain (`cm_clone_stored`), **not** JSON-RPC fork.
- Rollback: reload the pre-input checkpoint (`restore_rejected`), or discard+reclone (`rotate_reverted`).
- `cm_write_reg`/`cm_write_memory` on a rollup machine: only in tests/measure, never in the live node or player.

## New defects found by testing Dave's exact call sequences

### DAVE-FLOWS-1: `cm_clone_stored` hard-links the writable-range files of a read-only stored machine; a SHARING_ALL load of the clone writes through to the source (corrupts the template and the content-addressed store)
- Status: **PROVEN**
- Area: store / load / clone (`os::clone_file`) vs Dave's `checkout` + `load_shared`
- Category: data-loss / silent state corruption (and, without root, a liveness failure)
- Where (emulator): `os::clone_file` (`src/os-filesystem.cpp:559-607`) chooses `hardlink_file` when `(st.st_mode & S_WRITE_ALL) == 0` (`:585`), i.e. purely by the file's **permission bits**; `machine::clone_stored` (`src/machine.cpp:488-539`) clones every range's `.bin` this way, including **writable ranges** (RAM, CMIO, flash). `os::map_memory` opens a backing file `O_RDWR` and maps it `MAP_SHARED` whenever `shared && !flags.read_only` (`src/os-mapped-memory.cpp:95,119,165`), using the **config's** `read_only`, not the file mode. As root (CAP_DAC_OVERRIDE), `open(O_RDWR)` on a mode-0444 file succeeds, so the mapping is writable and shared.
- Where (Dave): `Storage::checkout` = `cm_clone_stored(from, .work-*)` (`cartesi-rollups/node/src/storage/snapshots.rs:249-258`); `RollupsMachine::load_shared` = `cm_load_new(SHARING_ALL)` (`storage/rollups_machine.rs:267-279`); the runner feeds and runs on that clone (`storage/advance.rs:358-401`, `machine_runner/mod.rs:128-192`). The epoch-0 seed and every published boundary are produced by `publish_staged`/`commit_clone` from such clones (`snapshots.rs:203-258`, `storage/open.rs:204-221`).
- Problem: Dave's whole design assumes "commit snapshots immutable, loaded SHARING_NONE; the working clone is a cheap COW copy that leaves the source untouched" (`docs/node-architecture.md:228-237`). That holds when the stored files are writable (reflink/CoW) — the normal case when the template was written by `cartesi-machine --store` (mode 0644). But when the **template directory is read-only** — a packaged/immutable app image, a Nix store path (Dave's docs make the Nix devshell the default provider), or an operator `chmod -R a-w` on a deployed asset — `clone_stored` hard-links its writable-range `.bin` files, so the clone **shares the inode** with the template and (because publication also clones) with the committed epoch-0 boundary. A `SHARING_ALL` load of the clone maps those inodes writable+shared, and the first guest write to RAM mutates the template and the CAS boundary in place.
- Scenario / impact:
  - **Silent (RAM-only read-only, e.g. the image file is read-only but sidecars are not)**: the template's stored `.dht/.dpt/.sht` still describe the *old* RAM, so `cm_load_new` returns the **row's root hash** and every Dave tripwire passes, while the data on disk is now a different state. The node settles commitments for a template nobody else can reproduce. Reproducer `ro_template ram`: loaded root == row key, but the data hashes from scratch to a different value; the published boundary differs from the honest computation. **BUG REPRODUCED.**
  - **Loud (whole template read-only)**: the sidecars are corrupted too, so the epoch-0 boundary no longer hashes to its row; dispute positioning hits `"the epoch start snapshot is corrupt"` and a restart's `Template::inspect` fails — the node is permanently stuck and its one authoritative template is destroyed. Reproducer `ro_template all`: template + CAS boundary both modified; load gives a root != row. **BUG REPRODUCED.**
  - **Without root** (drop `CAP_DAC_OVERRIDE`): the `SHARING_ALL` load fails `open()` with EACCES, so the whole node cannot start on a read-only template — a liveness failure instead of corruption (shown: `setpriv --bounding-set=-dac_override ./ro_template all` → `unable to open backing file ... Permission denied`). Rollup nodes very commonly run as root in containers, so the corrupting variant is the realistic one.
- Evidence: `<SCRATCH>/work/dave-flows/ro_template.c`; `bash run.sh` runs `ro-ram` (silent) and `ro-all` (loud), both exit 1 with `BUG REPRODUCED`; link-count output shows the clone's RAM `.bin` shares the inode (nlink 3). Clean under ASan+UBSan.
- Why this is not the gaps.md negative result: `<SCRATCH>/findings/gaps.md` §4 tested `clone_stored` with a **read-only flash drive** (config `read_only=true` → mapped `O_RDONLY`/private, genuinely isolated) and writable files (reflinked, isolated). The unsound case is a **writable range whose file is read-only on disk**, which only a read-only *stored template directory* produces — exactly Dave's seed input.
- Possible solution (emulator): in `clone_stored`, choose hardlink-vs-reflink by whether the **range is writable** (config `read_only`), not by the file's permission bits; or always reflink/copy range `.bin` files and only hardlink genuinely read-only ranges; or `clone_file` should refuse to hardlink a file it is about to hand to a writable `MAP_SHARED`. Defensively, `map_memory` for a writable shared range could refuse a file whose link count > 1, or copy-on-first-map. (Dave could also work around it by loading the template `SHARING_NONE` and re-storing, but the emulator's `clone_stored` contract — "read-only files are copied using hard links" — is the unsound part.)
- Severity: **High**. Silent corruption of the authoritative template and content-addressed boundaries → wrong, unprovable commitments; or a hard node stall. Conditional on (a) a read-only template directory and (b) the process having DAC override (root, typical in containers). Honest nodes with writable template dirs are unaffected.

### DAVE-FLOWS-2 (= CM-06 exposure): a damaged committed snapshot passes every Dave root-hash tripwire because `cm_load_new` trusts the stored hash tree
- Status: **PROVEN** (this is the Dave-reachable half of BUGS.md CM-06; recorded here as the concrete exposure, not a new emulator defect)
- Area: store / load / hash tree
- Category: data integrity / proof soundness
- Where (emulator): since v0.21 `cm_load` trusts the persisted `.dht/.dpt/.sht/.phtc` and never recomputes or compares the root (`machine.cpp` load path; BUGS.md CM-06). Where (Dave): every integrity check Dave has compares the **trusted loaded root** against the DB row — `assert_runner_boundary_root` (`snapshots.rs:94-115`), `publish_staged` (`:203-217`), `restore_rejected` (`machine_stf.rs:284-292`), `ruler_at` torn-snapshot skip (`:772-790`), `commit_boundary_machine` CAS assert (`snapshots.rs:136-152`). None rehashes the data.
- Problem/scenario: a committed `snapshots/0x<hash>` directory damaged after publication (bit rot, a partial filesystem restore, external mutation — the node-architecture doc calls external store mutation "unsupported" but has no detection) in a RAM page that is clean in the stored write-TLB loads with its original root and passes all of the above; the runner resumes from it and publishes/settles a state that differs from the honest computation.
